# Scaffolding (step 4)

If a conventions skill for the language is installed, load it. The rules below say Go; in other languages use the same idea: a stub is `throw new Error("TODO: <PR>")` or `raise NotImplementedError("TODO: <PR>")`, and the doc comment is a JSDoc or docstring. `<PR>` is the planned PR (`PR 2`) or its ticket key until the PR exists, then its number.

- **Types.** Domain types, value objects with their constructor and validation rule, domain errors, state enums. If the repo has a domain layer, it imports nothing from adapters, transport or SDKs.
- **Interfaces.** Shape them with `codebase-design`: a small interface with the behavior behind it, at a seam where something really varies (one adapter is a hypothetical seam, two is a real one). Define each port in the consuming package. When an existing interface gains methods, add them to every existing fake too, with stub bodies, so the tests still compile. Never add a method to an exported interface that other repos pin by version: their implementations break on the next bump. Declare a new interface instead.
- **Shared contracts.** The contract package shared across modules: request/response models and client methods. This is the only thing modules share besides IDs.
- **Entry points.** Routes or handlers in a function that nothing mounts yet; export it, or an `unused` linter fails. Workflow, job or consumer signatures with name, ID scheme, input, output and the messages they take. Repository methods on the db adapter.
- **Error kinds.** Each marked permanent or retryable.
- **Stub bodies.** Every body is a stub (`panic("TODO: <PR>")` in Go), naming the PR that fills it. A body may be real only if it is one line that stores a value (a constructor, a field getter). Nothing is registered, routed or wired at startup, so production behavior does not change. If the framework registers every method of a type (for example a Temporal activity struct), put new stubs on a type that isn't registered yet. It must compile and pass lint.
- **Generated files.** If a type change breaks a snapshot or other generated file, regenerate it. Do not regenerate API docs (for example swagger) for routes that aren't mounted.
- **Libraries.** Do not export a new option, function or type before the PR that fills it: a release on merge would ship something that does nothing.
- **Doc comments.** Every exported declaration gets one that states its contract: what it does, who calls it, what each error means, permanent or retryable. The comments are the spec the reviewer reads.
- **Multi-module Go repos.** If a contract module in the same repo is pinned by version, check who else imports it (`gh search code --owner <org> <module path> --filename go.mod`). Never add `replace` to a module other repos import: Go ignores it there, and their next bump breaks. Commit the contract module first, push, and pin every consumer to that commit's pseudo-version. If the repo squash-merges, say in the PR that main must re-pin after merge. Check the build with `GOWORK=off`.
